# ADR 006: 一時WAVは、JavaFXが手放してから消す

## Status

Accepted

## Context

ADR 005で、m4aを一時的なWAVファイルに変換し、JavaFXの`MediaPlayer`で再生すると決めた。一時WAVは、1曲で数十MBになる。曲を替えるたびに残していくと、一時フォルダが大きくなる。そのため、使わなくなった一時WAVは消す必要がある。

Windowsでは、どこかのプロセスが開いているファイルを消せない。JavaFXの`Media`は、`MediaPlayer`を`stop()`して`dispose()`したあとも、ファイルを開いたままにする。ファイルを閉じるのは、`Media`がガベージコレクションされたときである。

プローブで試した結果は、次のとおりである。1曲目のWAVは、`dispose()`の直後に消せた。2曲目以降のWAVは、`dispose()`の直後に消せず、2秒待っても消せなかった。`System.gc()`を挟むと、約30ms後に消せた。

アプリの中では、`MediaMusicPlayer`が2つ動く。プレイヤー画面のものと、重複一覧の試聴のものである。それぞれが、自分の一時WAVを持つ。

アプリは、異常終了することがある。そのときは、消す処理が動かない。また、正常に終了するときでも、その時点でJavaFXがファイルを開いたままのことがある。

## Decision

一時WAVは、JavaFXが手放したあとに消す。消す時期を決めるのに、`System.gc()`は呼ばない。ガベージコレクションの時期は、JVMに任せる。

一時WAVは、OSの一時フォルダの中の専用フォルダ（`sss-music-player`）に作る。アプリのほかのファイルと混ざらないようにし、まとめて消せるようにするためである。

`MediaMusicPlayer`は、次のように一時WAVを消す。

- 別の曲を再生するときに、前の一時WAVを消してみる。消せなければ、消し残しとして覚えておく。
- 再生するたびに、覚えている消し残しを消し直す。再生のたびに`Media`を作るので、そのうちガベージコレクションが走り、ファイルが閉じられる。
- 同じ曲を再生し直すときは、その一時WAVを消さずに使い回す（ADR 005）。

アプリの起動時に、専用フォルダに残った一時WAVをすべて消す。異常終了で残ったものや、前回の終了時に消し残したものも、ここで消える。起動の時点では、このアプリはまだどのファイルも開いていない。

アプリの終了時には、一時WAVを消さない。終了の時点では、まだJavaFXがファイルを開いていることがあるためである。消し残しは、次の起動時に消える。

アプリを2つ同時に起動すると、あとから起動したほうが、先のアプリの一時WAVを消そうとする。再生中のWAVは開かれているので、Windowsでは消せない。開かれていない一時WAVは消えるが、先のアプリはそれを変換し直さずに使おうとして、再生に失敗する。この失敗は画面に表示される。同時に起動する使い方は想定しないので、これを許す。

## Alternatives

### Alternative 1: 消す前に`System.gc()`を呼ぶ

別の曲を再生するときに`System.gc()`を呼べば、すぐに消せる。一時WAVは、いつも多くても1つになる。しかし、ガベージコレクションをアプリから強いるのは、JVMの調整を乱す。`System.gc()`は、JVMの設定によっては無視される。消せることの保証にもならない。

### Alternative 2: 終了時に`deleteOnExit()`で消す

Javaの標準の仕組みで、コードが短い。しかし、終了の時点でJavaFXがファイルを開いていれば、消せない。異常終了したときは動かない。

### Alternative 3: 裏のスレッドで、一定の間隔で消し直す

再生しなくても、消し残しがいずれ消える。しかし、スレッドの管理が増える。再生しない間は`Media`が作られないので、ガベージコレクションも起きにくい。間隔をあけて消し直しても、効き目は小さい。

### Alternative 4: 一時WAVを1つのファイル名で上書きして使い回す

ファイルが増えない。しかし、前の曲のWAVが開かれている間は、上書きもできない。結局、手放されるのを待つ必要がある。

## Confidence Level

確信度は中程度である。

手元のPCで、`dispose()`のあともファイルが開かれたままになること、ガベージコレクションのあとに消せることを、プローブで確かめた。再生のたびに消し直す仕組みで、消し残しが消えることも、テストで確かめた。ただし、そのテストは`System.gc()`を呼んでいる。アプリの実際の使い方で、どのくらいの間に消えるかは、まだ測っていない。

ファイルを開いたままにするのは、JavaFXの内部の振る舞いである。仕様として書かれたものではない。JavaFXの版が変われば、変わることがある。

native imageでも同じ振る舞いになるかは、まだ試していない。native imageのガベージコレクタは、JVMとは別のものである。

次のときは、この決定を見直す。

- JavaFXが、`dispose()`でファイルを閉じるようになったとき。
- 一時フォルダに、消し残しが多くたまることが分かったとき。
- m4aを一時WAVに変換するのをやめたとき（ADR 005を見直したとき）。

## Consequences

### 良い結果

一時WAVは、いずれ消える。消し残しがあっても、遅くとも次の起動時に消える。異常終了で残ったものも、同じく消える。

アプリから`System.gc()`を呼ばずに済む。JVMの調整を乱さない。

### 悪い結果

使わなくなった一時WAVが、一時的に2つ以上残ることがある。1つで数十MBなので、一時フォルダを数百MB使うこともありうる。

起動時に専用フォルダを消すので、アプリを2つ同時に起動すると、先のアプリの再生に失敗することがある。

消し残しのテストは、ガベージコレクションに頼る。テストの中で`System.gc()`を呼ぶので、JVMによっては時間がかかることがある。

### 中立的な結果

ADR 005の一時WAVを消す時期の記述は、このADRに移す。ADR 005には、このADRへの参照を残す。

`WavConverter`は、一時WAVを専用フォルダに作る。起動時に専用フォルダを空にする処理を、アプリの起動の流れに加える。
